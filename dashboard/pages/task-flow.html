monitor_agent.py → {status, step, risk_score, 温度/能量/异常} 与 sim_status 互补互验;两边数字不一致要指出并查因。risk_score ≥ 60 = 预防介入线。盯前几千步曲线再逐步放长间隔。
monitor_agent.pymcp__mdsim__sim_status
⚠ 异常 / CRITICAL / risk≥60 → 进 Mode C 修复支路: ① 确诊(四真相源 + 直读 log.lammps,找第一根因,不重复已失败策略)→ ② subagent 蜂群四路联网搜证(官方文档/邮件列表/社区帖/本体系已知坑)→ ③ AI 比选(机理对本 case 是否成立 + 来源置信度,比选过程对话可见)→ ④ 逐项执行铁律:一次一变量、先备份、ffield 永不改、每项判【成/败/不确定】、修复日志.md 记一笔、预算 3 项 → ⑤ 全败停下汇总,请用户决策。修好 → 回到 ⑦ 继续监控。
